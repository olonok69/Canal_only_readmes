# Missing Practices Classification Toolkit

This project enriches a catalogue of veterinary practices by combining multiple research pipelines with Azure OpenAI powered classification. It provides interchangeable data gathering strategies (Perplexity, Firecrawl, Google Custom Search) together with a comparison utility so you can evaluate how the different pipelines behave on the same batch of companies.

The repository currently centres around five primary scripts:

1. `tag_missing_practices.py` &mdash; legacy Perplexity-based enrichment pipeline.
2. `tag_missing_practices_firecrawl.py` &mdash; Firecrawl search and scrape flow feeding Azure OpenAI.
3. `tag_missing_practices_google.py` &mdash; Google Custom Search based enrichment feeding Azure OpenAI.
4. `compare_classifications.py` &mdash; benchmarking harness that runs the other classifiers side by side and emits a Markdown comparison.
5. `firecrawl_bot.py` &mdash; ad-hoc Q&A bot that scrapes supplied URLs with Firecrawl and answers questions via Azure OpenAI. When you do not pass any URLs it automatically loads context from `https://www.promptingguide.ai/` so you can begin chatting immediately and then layer in additional sources on demand.

Supporting data lives under `data/` and includes the registration exports and lookup tables required to seed the classification prompts.

## 1. Installation & Environment Setup

### Prerequisites

- Python 3.11+ (the project has been exercised on Python 3.13.3).
- Ability to create and activate a virtual environment (`python -m venv .venv`).
- API credentials for the external services you plan to use (Perplexity, Firecrawl, Google Custom Search, Azure OpenAI).

### Install Dependencies

```powershell
# From the repository root
ython -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

The requirements file covers the shared stack (`pandas`, `python-dotenv`, `langchain-openai`), together with optional clients:

- `perplexityai` for the legacy Perplexity integration.
- `firecrawl-py` (Firecrawl search + scrape).
- `google-api-python-client` and `requests` for Google Custom Search plus page fetching.

### Environment Variables

All scripts load credentials from `.env` via `python-dotenv`. Populate the file with any of the variables listed below (only the ones relevant to the scripts you run are strictly required).

| Variable | Purpose |
| --- | --- |
| `AZURE_API_KEY`, `AZURE_ENDPOINT`, `AZURE_DEPLOYMENT`, `AZURE_API_VERSION` | Azure OpenAI deployment used for classification across all pipelines. |
| `PERPLEXITY_API_KEY`, `PERPLEXITY_MODEL` | Needed only by `tag_missing_practices.py`. |
| `FIRECRAWL_API_KEY` | Required by `tag_missing_practices_firecrawl.py`. |
| `GOOGLE_API_KEY` or `GOOGLE_DEVELOPER_API_KEY` | API key for Google Custom Search. |
| `GOOGLE_SEARCH_ENGINE_ID` | Custom Search Engine (CSE) ID tied to your Google key. |
| Optional tuning variables | `SSL_ENABLED`, etc., are read elsewhere (leave if already present). |

> **Tip:** Stripe duplicate entries out of `.env`; only one instance of each Google key should remain.

## 2. Shared Data Inputs

All classification scripts expect the same input CSV files:

- `data/missing_practice_companies_lva2025.csv` &mdash; master list of companies still missing tags (generated by `find_missing_practices.py`).
- `data/practices_missing.csv` &mdash; canonical catalogue with existing enrichments.
- `data/Registration_data_with_demographicdata_bva_this.csv` &mdash; in-depth registration export used to build prompts.
- `data/spezialization_to_stream.csv` &mdash; allowed taxonomy (e.g. Small Animal, Equine).

Each script validates the taxonomy file and reuses helper utilities from `tag_missing_practices.py` to ensure consistent normalisation (`normalizedCompany`, chunking, etc.).

## 3. Script Reference

### 3.1 `tag_missing_practices.py` (Perplexity Pipeline)

**Purpose:** Original workflow using Perplexity's chat completions API to perform research + classification in a single step.

**Key Flow:**

1. Load missing companies and ensure they are not already present in `practices_missing.csv`.
2. Chunk companies (`--batch-size`) and build prompts containing registration context.
3. Call Perplexity (`call_perplexity`) using web search domain filters derived from known email domains.
4. Parse JSON response, enforce allowed tags, and append results to the catalogue (unless `--dry-run`).

**Important CLI Options:**

| Flag | Description |
| --- | --- |
| `--limit` | Process only the first *N* qualifying companies. |
| `--dry-run` | Print proposed entries instead of writing to CSV. |
| `--batch-size` | Companies per API request. |
| `--company` | Target specific company names or normalised IDs. |
| `--temperature`, `--max-tokens`, `--model` | Pass-through tuning for Perplexity. |

**Example:**

```powershell
python tag_missing_practices.py --limit 10 --dry-run --verbose
```

### 3.2 `tag_missing_practices_firecrawl.py` (Firecrawl + Azure Pipeline)

**Purpose:** Replace Perplexity with Firecrawl search/scrape while keeping Azure OpenAI for classification. This mirrors the Perplexity flow but decouples research from tagging.

**Key Flow:**

1. Build Firecrawl queries using company metadata plus `--query-keywords`.
2. Execute Firecrawl search (`FirecrawlResearcher.fetch`) and optionally scrape top hits (`--firecrawl-scrape-top`) into markdown excerpts.
3. Embed search summaries and snippets into the Azure prompt.
4. Invoke Azure OpenAI via `langchain_openai` and post-process identical to the legacy script.

**Notable Options:**

| Flag | Description |
| --- | --- |
| `--firecrawl-limit` | Max search results ingested per company. |
| `--firecrawl-scrape-top` | Number of results to scrape for full content. |
| `--firecrawl-scrape-formats` | Request formats from Firecrawl (default markdown). |
| `--firecrawl-location`, `--firecrawl-tbs`, `--firecrawl-categories` | Search tuning knobs. |
| `--query-keywords` | Extra search terms appended to each query. |

**Example:**

```powershell
python tag_missing_practices_firecrawl.py --dry-run --limit 5 --verbose --firecrawl-scrape-top 8
```

**Operational Notes:**

- Firecrawl cannot scrape certain domains (e.g. Facebook, Yelp); the script logs friendly DEBUG warnings and continues.
- The `_normalize_results` helper handles both `data.web` style payloads and top-level `web/news` keys.

### 3.3 `tag_missing_practices_google.py` (Google CSE + Azure Pipeline)

**Purpose:** Provide a third research path using Google Custom Search (with optional HTML fetches) to supply evidence for Azure OpenAI classification.

**Key Flow:**

1. Issue Custom Search API requests with optional language (`--google-language`), geo (`--google-country`), and time (`--google-date-restrict`) filters.
2. Capture search snippets and optionally fetch top pages to extract text excerpts via `_strip_html`.
3. Assemble Firecrawl-style dossiers referencing Google results and pass them to Azure OpenAI.
4. Parse responses and write/dry-run outputs identical to the other pipelines.

**Notable Options:**

| Flag | Description |
| --- | --- |
| `--google-num` | Number of search hits to consider (API caps at 10 per call). |
| `--google-fetch-top` | Count of top results to download for excerpts. |
| `--google-fetch-char-limit` | Truncate fetched pages to keep prompts concise. |
| `--google-language` / `--google-country` / `--google-date-restrict` | Map to Custom Search parameters `lr`, `gl`, `dateRestrict`. |

**Example:**

```powershell
python tag_missing_practices_google.py --dry-run --limit 5 --verbose --google-fetch-top 8
```

**Operational Notes:**

- Uses the official `google-api-python-client`; set `GOOGLE_API_KEY` and `GOOGLE_SEARCH_ENGINE_ID`.
- Page fetching relies on `requests` with a desktop User-Agent; unreachable pages simply emit DEBUG logs.

### 3.4 `compare_classifications.py` (Cross-Pipeline Comparator)

**Purpose:** Run the three classification scripts back-to-back with consistent arguments, parse their dry-run outputs, and produce either a detailed Markdown report or a summary table.

**Usage Pattern:**

1. Each pipeline is executed through `subprocess.run`; the script expects dry-run logs containing lines such as `Proposed entry -> …` and `Justification: …`.
2. Parsed results are aggregated by company ID.
3. The final report is printed or written to file (`--output`).

**Key Options:**

| Flag | Description |
| --- | --- |
| `--firecrawl-args`, `--perplexity-args`, `--google-args` | CLI fragments passed to each underlying script. Defaults mirror the recommended dry-run commands. |
| `--summary` | Switch between the detailed per-company narrative and a compact Markdown table (`| Company | Firecrawl | Perplexity | Google |`). |
| `--output` | Save the comparison to disk instead of printing. |

**Examples:**

```powershell
# Detailed view
python compare_classifications.py

# Summary table saved to file
python compare_classifications.py --summary --output comparisons.md
```

**Operational Notes:**

- Raises on non-zero exit codes from any pipeline (helpful during debugging).
- Warns if no `Proposed entry` lines were parsed, hinting at upstream configuration issues.

### 3.5 `firecrawl_bot.py` (Firecrawl-Powered Q&A Bot)

**Purpose:** Quickly answer arbitrary questions about specific URLs by scraping those pages with Firecrawl and forwarding the curated excerpts to an Azure OpenAI deployment. If you launch the bot without passing `--url` it preloads `https://www.promptingguide.ai/` as background reading so you can start a conversation immediately, then layer in additional context URLs as the discussion evolves. Supports single-shot queries, an interactive chat mode with conversational memory, or a LangChain agent mode that calls Firecrawl tools on demand.

**Key Flow:**

1. Accept one or more `--url` arguments plus a `--question`.
2. Scrape each URL via Firecrawl (markdown/text formats) and trim the excerpts to fit within configurable character budgets.
3. Build a structured dossier citing each source URL and submit it to Azure OpenAI via `langchain_openai`.
4. Optional `--interactive` mode reuses the dossier, lets you add URLs mid-session, and streams answers with conversational memory.
5. Optional `--agent` mode swaps in a LangChain agent that uses Firecrawl search/scrape as a tool (auto-applying `site:<domain>` when `--site-root` is provided) and keeps chat history via `ConversationBufferMemory`.

**Important CLI Options:**

| Flag | Description |
| --- | --- |
| `--url` | Target URL to scrape (repeatable). Defaults to `https://www.promptingguide.ai/` when omitted. |
| `--question` | Natural-language question answered using the scraped context (omit for chat). |
| `--interactive` | Launches a REPL-style chat with `/add`, `/sources`, `/exit` commands. |
| `--memory-turns` | Number of previous user turns preserved in the prompt. |
| `--agent` | Enables LangChain agent mode; Firecrawl becomes a tool the LLM can call. |
| `--site-root` | Preferred domain for agent searches (adds `site:<domain>` to queries). |
| `--agent-search-limit`, `--agent-scrape-top`, `--agent-scrape-char-limit` | Control how much content each Firecrawl tool call returns. |
| `--firecrawl-formats` | Preferred Firecrawl formats (default `markdown`). |
| `--firecrawl-char-limit` | Max characters kept per URL to control prompt size. |
| `--max-sources` | Limits how many URLs are included once duplicates are removed. |
| `--temperature`, `--max-tokens`, `--azure-deployment` | Standard Azure OpenAI tuning knobs. |

**Example:**

```powershell
# Start a conversation using the default prompting guide context
python firecrawl_bot.py --interactive --memory-turns 6

# Single question with an explicit context URL
python firecrawl_bot.py \
	--url https://example.com/docs/product \
	--question "What deployment options are documented?" \
	--firecrawl-char-limit 1500

# LangChain agent exploring an entire site
python firecrawl_bot.py \
	--agent --site-root https://example.com \
	--question "List compliance documents published this year" \
	--agent-search-limit 5 --agent-scrape-top 3
```

**Operational Notes:**

- Shares the same Azure client and Firecrawl payload utilities as `tag_missing_practices_firecrawl.py` to keep behaviour consistent.
- Emits warnings if Firecrawl cannot scrape the URL; at least one excerpt is required before contacting Azure.
- Chat mode deduplicates URLs, keeps a running history (bounded by `--memory-turns`), and lets you inject new sources mid-session via `/add <url>`.
- Whenever no URLs are provided the session banner lists the default sources so you know exactly which documents back the answers.
- Agent mode relies on LangChain's `ConversationBufferMemory`; Firecrawl tool calls automatically respect `--site-root` scopes when provided.

## 4. Typical Workflow

1. **Prepare inputs** with `find_missing_practices.py` (outside scope of this README) to populate `data/missing_practice_companies_lva2025.csv`.
2. **Pick a research pipeline** based on desired evidence sources (Perplexity, Firecrawl, Google) and run it in `--dry-run` mode while tuning query parameters.
3. **Inspect logs** for search richness and Azure responses (`--verbose` recommended during tuning).
4. **Commit classifications** by rerunning without `--dry-run`; the script merges new predictions into `data/practices_missing.csv` while preserving existing entries.
5. **Benchmark** using `compare_classifications.py` to spot divergences across pipelines before finalising updates.

## 5. Troubleshooting & Tips

- **Missing credentials:** All scripts raise descriptive `RuntimeError`s if the required API keys are absent. Double-check `.env` loading order.
- **Unsupported domains:** Firecrawl scrapes only a subset of the web. Expect `Website Not Supported` warnings for Facebook, Yelp, etc. Google pipeline can often fetch those pages directly if public.
- **Token limits:** Adjust `--max-tokens` and `--google-fetch-char-limit`/`--firecrawl-scrape-char-limit` if Azure prompts grow too large.
- **Filtering specific companies:** Use `--company "Normalized Name"` (mirrors the normalisation logic in `find_missing_practices`) to target outliers without reprocessing the entire data set.
- **Reproducibility:** Keep a record of CLI parameters used for production runs; the comparison script arguments provide a convenient template.
