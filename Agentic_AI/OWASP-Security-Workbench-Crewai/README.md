# OWASP Security Workbench (Streamlit + CrewAI)

Unified security exploration and review workspace for:

- Browsing **OWASP Cheat Sheets** (live scrape + structured parsing + cache)
- Exploring **OWASP Top 10** datasets (LLM Top 10 static + OWASP Top 10 2025 web/local)
- Running **AI-assisted code reviews** against selected OWASP guidance
- Generating and loading **local JSON artifacts** via CrewAI workflows

This repository combines a user-facing Streamlit application with multiple CrewAI-based automation workflows for content extraction and review.

---

## 1) What this application does

The main app (`app.py`) provides two operating sections:

1. **Cheat Sheets**
   - Fetches OWASP cheat sheet index from `Glossary.html`
   - Lets users open individual cheat sheets in rich views (overview, risks, matrix, resources)
   - Supports local checksheet JSON generated by `agents/checksheet_crew`

2. **Top 10**
   - Supports multiple data sources from `owasp_llm/config.yaml`
   - Uses built-in static LLM risk dataset for `llm_top10_2025`
   - Can scrape/parse OWASP Top 10 web content for `owasp_top10_2025`
   - Supports local Top 10 JSON generated by `agents/top10_crew`

Both sections include a shared **Code Review panel** that can run a CrewAI review workflow on uploaded files or pasted diffs, producing Markdown reports under `report/`.

---

## 2) Core capabilities

- **Live content acquisition** via Firecrawl API
- **Schema-based parsing** to Pydantic models (`src/models.py`)
- **Disk cache with expiry + size limits** (`src/cache_manager.py`)
- **Top 10 and Cheat Sheet context packaging** for guided code review
- **CrewAI orchestration** for:
  - check sheet JSON generation
  - top 10 JSON generation
  - code quality/security review and recommendations
- **Report lifecycle**: generate, view, and download review reports in app

## 4) Architecture

![Application Architecture](docs/images/architecture.svg)

### Main app layers

1. **UI Layer (`app.py`)**
   - Sidebar-driven navigation and source selection
   - Section renderers: Overview, All Risks, Risk Details, Attack Examples, Risk Matrix, Resources, Reports

2. **Service Layer (`src/`)**
   - `config_manager.py`: YAML + env substitution (`${VAR}`)
   - `firecrawl_client.py`: scrape/crawl client, retries, throttling
   - `cheatsheet_parser.py`: glossary/index/page parsing into structured model
   - `cache_manager.py`: disk cache entries with TTL + metadata + size cleanup

3. **Model Layer (`src/models.py`)**
   - `CheatSheet`, `RiskItem`, `AttackExample`, `CheatSheetIndex`, etc.

4. **Data Layer**
   - Static LLM Top 10 dataset (`src/top10_data.py`)
   - Local generated JSON (`data/checksheets`, `data/top10`)
   - Runtime cache (`cache/`) and reports (`report/`)

### CrewAI workflows

- `agents/checksheet_crew`: turns one cheat sheet URL into app-compatible checksheet JSON
- `agents/top10_crew`: turns a Top 10 URL into app-compatible Top 10 JSON
- `agents/code_review_crew`: multi-agent code review (quality + security + summary)
- `agents/code_review_flow`: flow-based orchestration example with routing for simple vs complex diffs

## 8) Configuration & environment

Create a `.env` file at repo root:

```env
FIRECRAWL_API_KEY=your_firecrawl_key
OPENAI_API_KEY=your_openai_key
SERPER_API_KEY=your_serper_key
```

Notes:

- `FIRECRAWL_API_KEY` is required for **Live OWASP (Firecrawl)** mode.
- `OPENAI_API_KEY` / `SERPER_API_KEY` are required for most CrewAI tasks.
- `ConfigManager` loads `.env` from current working dir first, then module root.

Main app config (`config.yaml`) controls:

- Firecrawl settings (`base_url`, `timeout`, retries)
- Cache behavior (`expiry_days`, `index_expiry_days`, size limit)
- Rate limiting (`requests_per_minute`)
- Logging output and level

## 10) Ways of working (recommended workflows)

### Workflow 1 — Security knowledge exploration (UI-first)

1. Open app in Cheat Sheets mode
2. Use live data for latest guidance
3. Filter by category and inspect risk details/mitigations
4. Use Risk Matrix for severity comparison

Best for: learning, policy alignment, architecture discussions.

### Workflow 2 — Curated offline/local dataset generation

Generate checksheet JSON (PowerShell):

```powershell
$env:CHEATSHEET_URL="https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html"
python agents/checksheet_crew/main.py
```

Generate Top 10 JSON (PowerShell):

```powershell
$env:TOP10_URL="https://owasp.org/Top10/2025/"
python agents/top10_crew/main.py
```

Then in app sidebar choose local sources:

- `Local Checksheet JSON` (reads `data/checksheets/*.json`)
- `Local Top 10 JSON` (reads `data/top10/*.json`)

Best for: repeatable demos, workshops, low-latency/offline-ish review sessions.

### Workflow 3 — PR/diff review against OWASP context

1. Select context (Cheat Sheet or Top 10 source)
2. Paste diff and/or upload changed files
3. Run code review panel
4. Open generated report in Reports page
5. Download/share report with development team

Best for: pre-review triage and actionable fix planning.

## 11) Caching and performance behavior

- Cheat sheet index is cached separately (shorter TTL)
- Individual page content is cached with longer TTL
- Top 10 web parses are cached under source-specific cache keys
- `Clear Cache` in sidebar removes disk cache and Streamlit data cache

Default behavior from `config.yaml`:

- content expiry: 90 days
- index expiry: 7 days
- cache size cap: 500 MB

## 12) Security review automation details

The in-app review panel dynamically loads `agents/code_review_crew/crew.py` and executes `CodeReviewCrew().crew().kickoff(...)`.

Current crew design:

- `senior_developer`: code quality review
- `security_engineer`: security review with OWASP-oriented search/scrape tooling
- `tech_lead`: synthesized findings/recommendations summary

Outputs are structured JSON (via Pydantic task schemas), then transformed into Markdown reports.

## 13) Troubleshooting

### No cheat sheets in live mode
- Confirm `FIRECRAWL_API_KEY` is set
- Confirm network access to Firecrawl + OWASP
- Use sidebar `Clear Cache` and reload

### No local JSON files appear
- Ensure files exist in expected directories:
  - `data/checksheets/*.json`
  - `data/top10/*.json`

### Code review fails at runtime
- Confirm `OPENAI_API_KEY` and `SERPER_API_KEY`
- Verify CrewAI dependencies installed from `requirements.txt`
- Check terminal logs and `logs/` output

### Rate-limit or scraping failures
- Reduce request pressure, retry later
- Adjust timeout/retry/rate-limit values in `config.yaml`

---

## 14) Limitations and expectations

- Live content quality depends on upstream page structure and Firecrawl extraction quality
- Parsed risk metadata (severity/types/mitigations) is heuristic for some sources
- AI code review provides decision support, not a guaranteed security audit
- Generated local datasets should be periodically refreshed

---

## 15) Developer notes

- Keep model and schema compatibility between app loaders and crew outputs
- If adding data sources, update `owasp_llm/config.yaml`
- If extending risk parsing logic, prefer updating parser functions in `src/cheatsheet_parser.py` and corresponding renderers in `app.py`
- Preserve cache key strategy and TTL semantics to avoid stale or duplicate artifacts
